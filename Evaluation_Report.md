## 1. Comparative Analysis: Multi-Threading vs Multi-Processing

| Metric | Multi-Threading | Multi-Processing |
| --- | --- | --- |
| Wall Clock Time | 242.69 ms | 3382.81 ms |
| Context Switch Overhead | 42.69 ms | 3182.81 ms |
| Avg Overhead per Switch | 1.0673 ms | 79.5702 ms |

**Conclusion**: Multithreading exhibits significantly lower context switching overhead than multiprocessing because all threads share the same memory space, requiring no memory paging updates by the OS. Multiprocessing requires complete process isolation and separate memory allocation (enforced by OS), drastically increasing context switch times.

## 3. Environment & Resource Limitations

### Low vs High Memory Impact

| --- | --- | --- |
| High Memory (4096MB) | 363.85 | 12.67% |
| Low Memory (128MB) | 251.30 | 79.55% |

**Conclusion**: Under strict memory constraints, processes are starved in the NEW queue until previous processes terminate. This directly inflates Waiting Time and Turnaround Time, highlighting how RAM limits can bottleneck CPU performance.

### Host vs Docker Performance

As demonstrated using Linux monitoring tools (`Analysis_Guide.md`), the unconstrained host machine will utilize all available cores. By deploying the simulator in a Docker container with `--cpus='1.0'`, we enforced an artificial ceiling. When the container reaches 100% usage of that single slice, `top` shows the python process throttled, thereby reducing throughput drastically compared to an unconstrained host.
